# Implementation Plan: dbt Fusion Compatibility, Macro YMLs, Tests, CI Pipeline & CODEOWNERS

## Context

This is a **pure macro/materialization dbt package** (no models, seeds, or snapshots) with 25 macro files across 3 domains: agents, cortex search, and semantic views. Currently there are:
- **Zero YML property files** for any macros
- **Zero tests**
- **No CI pipeline** (`.github/` directory doesn't exist)
- **No CODEOWNERS file**

### dbt Fusion Compatibility Findings

After reviewing all 25 macros against dbt Projects on Snowflake (dbt Fusion) requirements:

1. **`flags.WHICH`** — Used in 7 grant macros. This is a standard dbt Core flag and is supported in dbt Fusion. No change needed.
2. **`run_query()`** — Used extensively in grant macros. This is standard dbt Jinja and works in dbt Fusion.
3. **`env_var()`** — NOT used anywhere. Good, since it's unsupported in Fusion.
4. **Custom materializations** — The `agent` and `cortex_search` materializations use standard dbt patterns (`set_query_tag`, `api.Relation.create`, `load_relation`, `run_hooks`, `statement`). These are compatible.
5. **`->>` pipe operator** — Used in 3 ownership grant macros (`SHOW ... ->> SELECT ...`). This is a Snowflake SQL feature, not a Jinja feature, and works fine.
6. **Typo bug** — `macros/relations/agents/alter.sql:12` has `"modify live vesion"` — should be `"modify live version"`. This is a real bug.
7. **All macros are compatible with dbt Fusion** — no env_var usage, no unsupported flags, standard Jinja patterns throughout.
